## v0.1.0 — первый рабочий выпуск (2026-11-16)

**Суть:** Telegram-бот трижды в день расспрашивает пользователя, складывает ответы в Obsidian
и собирает локальный дашборд. Всё на Mac, без облака, без внешних библиотек.

### Что умеет

- Bot API long polling, один `chat_id`; 429/409/401 обрабатываются, цикл не падает.
- Слоты 08:30 / 14:00 / 21:30 (Europe/Moscow), догон 180 мин, TTL сессии 12 ч.
- Диалог с уточнениями (≤2), «-»/«стоп»/`/статус`, свободный чат в любой момент.
- 12 команд + русские алиасы; `/add_goal Название | 3/10 | срок`.
- Obsidian: daily из шаблона, маркеры без дублей, таблица целей, зеркало JSONL/JSON.
- Дашборд: один HTML без CDN, 10 карточек, пересборка после записи, пустые состояния без NaN.
- Установка: `install.sh` → `~/Library/Application Support/LifeOS`, LaunchAgent
  `com.lifeos.agent` (RunAtLoad + KeepAlive), конфиг 600, подхват `DDD_API_KEY`.
- LLM опционален: SAMP `deepseek-v4.1-flash-1017` + скриптованный fallback.

### Известные проблемы

1. **Прогресс убывающих целей врёт:** «Похудеть до 78 кг» при весе 78 → 100%
   (`current/target` без направления). Обход: `/add_goal … | 3/10`. Фикс — backlog #3 (P0).
2. **`weekly` выключен** — фаза 2, заметка `01 Неделя` не создаётся.
3. **Ротация stdout-лога:** `RotatingFileHandler` крутит `data/logs/agent.log`, а
   `~/Library/Logs/LifeOS/agent.log` от launchd растёт без ротации (backlog #4).
4. **Full Disk Access** может потребоваться для записи в `~/Documents` (backlog #5).
5. **Живой запуск не проверен:** токена нет; установка — только `--dry-run` + 12 тестов.
6. **Мобильная вёрстка и контраст:** проверено в Safari (`UX_REVIEW.md`): на 390 шапка
   развалилась, сетка на 1024 с дырами, подписи графиков 6–8 px, контраст 2,27:1.
7. **Демо пересобрано (2026-11-17):** `demo/index.html` = 2 559 строк, 140 КБ, данные
   подставлены в `window.LIFEOS_DATA`; структура совпадает с `dashboard/template.html`.
   Осталось открыть демо в браузере и посмотреть консоль — сборка проверена, отрисовка нет.
8. **Версии сведены (2026-11-17):** `VERSION` = `0.1.1`, `CHANGELOG.md` — верхняя секция
   `[0.1.1]`, `src/__init__.py:11` = `0.1.1`. Тег будет поставлен вместе с коммитом волны 3.

## Правила выпуска (чтобы история не разъезжалась)

1. Порядок: `CHANGELOG.md` → `VERSION` → `__version__` → `RELEASE_NOTES.md` (корень) →
   этот файл → тег. Любой пропуск = рассинхрон.
2. Семантика: пока нет живой установки и приёмки 7/7 по ТЗ §8 — версия `0.x`.
   `1.0.0` — только после T8 (реальный токен, сообщение по расписанию) и закрытых P0.
3. Секции `CHANGELOG.md`: `Добавлено` / `Изменено` / `Исправлено` / `Удалено`;
   пустой `[Unreleased]` перед выпуском.
4. Этот файл хранит историю версий и решения по релизу; пользовательские тексты —
   только в корневом `RELEASE_NOTES.md`, чтобы не было двух правд.
5. Автоматика: `check.sh` должен оставаться зелёным на каждом релизе; добавить в него
   сверку `VERSION` ↔ `__version__` (сейчас не сверяет).
