## Детали по P0

### QB-03 — направление цели

Сейчас: `progress = current / target`, обрезка 0..1 (`src/dashboard_data.py:436-458`).
Нужно: у цели есть старт (`start_value`) и направление. Для «похудеть до 78» при старте 92:
`(92 - current) / (92 - 78)`; при `current = 92` → 0%, при 78 → 100%. Для растущих целей —
текущая формула. Критерий готовности: цель «Похудеть до 78 кг» с текущим весом 78 и стартом
92 показывает 100%, с весом 92 — 0%, с весом 85 — 50%; тест в `tests/test_dashboard.py`.

### QB-05 — доступ к Obsidian

Проверка: при старте `Vault` пробует дописать служебную строку в `data_folder` или сделать
`ensure_daily(today)`; при `PermissionError`/`OSError` — лог + одно сообщение в Telegram со
ссылкой на README §9 и путём интерпретатора. Критерий: пользователь узнаёт о проблеме из
бота, а не из пустого дневника.

## Как пополнять

1. Дефект с воспроизведением → сразу P0 и ссылка на `DECISION_LOG.md`.
2. Идея без боли → не берём: сначала описать, что человек не может сделать сегодня.
3. У каждой записи — критерий готовности, иначе задача не закрывается.
4. Сделанное переносится в `RELEASE_NOTES.md`, а не удаляется отсюда.
