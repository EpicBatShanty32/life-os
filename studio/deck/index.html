03Свободный текст → LLM, если включён

LLM не обязателен: бот работает и без него.

LLM включён

Понимает свободный текст

  • уточняет вопрос по смыслу ответа
  • разбирает в category, text, metrics
  • лимиты: 30 с, 4000 символов, пауза после 3 ошибок
LLM выключен или упал

Работает по скрипту

  • заранее заготовленные вопросы
  • числа из текста: вода, сон, вес, км, минуты, калории
  • данные пишутся в любом случае
Ключ хранится в ~/.dsh/.credentials.yaml. install.sh переносит его в config.json с правами 600 и не печатает. В логи и git ключ не попадает. llm.enabled=false — без внешних запросов, кроме Telegram.

09Безопасность 09 / 11

Личные данные остаются личными

Не обещания, а границы: что где лежит, что уходит наружу и что проверяют тесты.

Секреты

  • config.json — 600, каталог data — 700, база — 600.
  • Токен не печатается в логах и в repr.
  • Ключ LLM и токен не попадают в git: config/, data/ и логи закрыты .gitignore.
  • check.sh ищет sk-… и токены ботов в проекте.

Локальность

  • SQLite, Obsidian-vault и дашборд лежат на Mac.
  • Наружу — только Telegram; LLM-шлюз включается отдельно.
  • llm.enabled=false → внешних запросов, кроме Telegram, нет.
  • Дашборд — один HTML без CDN, внешних шрифтов и картинок из сети.

Песочница

  • Тесты — temp-каталоги и мок Bot API; живая база не трогается.
  • Запись за пределы vault (../, симлинк наружу) отклоняется.
  • SQL — только параметры; <script> в данных экранируется.
  • --dry-run не пишет рабочее состояние.
Остаточный риск: при включённом LLM текст ответов уходит на шлюз api.samp.team. Это написано в README, /start и /help; режим отключается настройкой llm.enabled.
