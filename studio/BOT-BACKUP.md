# Если сломалась база: как восстановиться из копии

Короткая инструкция на случай, когда бот перестал отвечать или пишет ошибку про базу.
Всё делается на маке, в Терминале, копированием команд — по одной строке за раз.

Главное: **копия базы делается сама каждый день в 04:00 и ещё раз при каждом запуске бота**.
Копии лежат в папке `data/backups/` внутри проекта. Одна копия = один файл
`2026-11-18-04.db`: год-месяц-день-час. Хранятся 14 последних и по одной за каждый
прошлый месяц, поэтому вчерашняя и позавчерашняя копия всегда есть.

---

## Шаг 0. Открыть проект

```bash
cd /Users/user/Documents/deepseek-harness/default-workspace/life-os
```

Дальше все команды — из этой папки.

Служба бота ставится и проверяется одной командой — подробности в
[`ops/README.md`](../ops/README.md).

## Шаг 1. Посмотреть, какие копии есть

```bash
ls -lh data/backups
```

Видите файлы вида `2026-11-18-04.db` — значит копии есть. Самый свежий — сверху.

## Шаг 2. Проверить копию перед восстановлением

```bash
tools/restore-check.sh
```

Скрипт берёт самый свежий файл, разворачивает его во временную папку и считает
записи. В конце должна быть строка:

```
бэкап годен
```

Если написано «бэкап НЕ годен» — не восстанавливайте этот файл, возьмите копию
постарше:

```bash
tools/restore-check.sh data/backups/2026-11-17-04.db
```

(подставьте имя файла из шага 1). Добивайтесь строки «бэкап годен».

## Шаг 3. Остановить бота

```bash
bash tools/bot-service.sh stop
```

То же вручную, если служба не отвечает:
`launchctl bootout gui/$(id -u)/com.lifeos.bot 2>/dev/null; pkill -f app.bot.main 2>/dev/null; true`

Если бот был запущен в окне Терминала — там достаточно нажать `Ctrl+C`.

## Шаг 4. Отодвинуть испорченную базу в сторону

Ничего не удаляем — просто переименовываем, чтобы можно было вернуться:

```bash
mv data/lifeos-v3.db "data/lifeos-v3.db.broken-$(date +%Y%m%d-%H%M)"
rm -f data/lifeos-v3.db-wal data/lifeos-v3.db-shm
```

Две строки — это одно действие: старая база убрана, служебные файлы рядом с ней
тоже (иначе SQLite попробует «дописать» их к новой базе).

## Шаг 5. Положить копию на место базы

```bash
cp data/backups/2026-11-18-04.db data/lifeos-v3.db
```

Имя файла — то, которое вы выбрали на шаге 2.

## Шаг 6. Убедиться, что база открывается и записи на месте

```bash
sqlite3 data/lifeos-v3.db "PRAGMA integrity_check; SELECT COUNT(*) FROM entries;"
```

Ожидаемый ответ — две строки: `ok` и число записей (например `929`).
Если вместо `ok` что-то другое — вернитесь к шагу 2 и возьмите другую копию
(перед этим повторите шаг 4, чтобы убрать неудачную базу).

## Шаг 7. Запустить бота

Если бот поставлен службой (обычный режим):

```bash
bash tools/bot-service.sh start
```

Если службы нет — запустить в окне Терминала:

```bash
bash tools/run-bot.sh
```

Окно закрывать нельзя, пока бот работает; остановить — `Ctrl+C`.
Поставить службу насовсем: `bash tools/bot-service.sh install`.

## Шаг 8. Убедиться, что всё живо

Напишите боту в Telegram `/backup`. Он должен прислать файл-копию и подпись
с размером. Значит бот читает базу, а копии снова делаются.

---

## Если что-то пошло не так

- **«бэкап НЕ годен» на всех копиях.** Восстанавливать нечего; база, скорее всего,
  цела, а проблема в другом — проверьте `data/logs/bot.log` и
  `data/logs/backup.log`.
- **Копий в `data/backups` нет.** Значит служба копий не установлена или не
  запускалась. Поставьте её: `deploy/install-backup-agent.sh`, и проверьте:
  `deploy/install-backup-agent.sh --status`.
- **Проверить, живы ли бот и автобэкап.** `bash tools/bot-service.sh status`
  покажет службу, процесс бота и последние строки лога;
  `deploy/install-backup-agent.sh --status` — службу копий и сами копии.
- **Хочу вернуть старую (испорченную) базу обратно.** Она лежит рядом:
  `data/lifeos-v3.db.broken-…` — повторите шаги 3–4 и скопируйте её на место
  `data/lifeos-v3.db`.
- **Куда попадают фото и голосовые.** Они лежат в `data/media/` и в копию базы
  не входят: копируется только база (все записи, цифры, планы). Файлы из
  `data/media` при желании скопируйте вручную, например на флешку.

## Что внутри копии

Один файл SQLite — та же база, что у бота, только снимок на момент копирования.
Его можно открыть любым просмотрщиком SQLite и вернуть на место простым
копированием. Служебных файлов рядом (-wal, -shm) у копии нет: она
самодостаточна.
