# Мозг бота: LLM вторым слоем (t39)

**Итог: готово, ключ уже есть.** Бот больше не «просто скрипт»: явные фразы
разбирают правила (быстро и бесплатно), свободные — модель с подсказкой
`reasoning.effort`, при любой ошибке — тихий откат на правила. Настоящий
`api.samp.team` проверен: поле `reasoning: {effort: "xhigh"}` принимается,
ответы приходят, ключ в логи не попадает.

## Как включить / выключить

Ключ уже лежит в `config/config.json → llm.api_key`; если его нет, бот берёт
`DDD_API_KEY` (или `LIFEOS_LLM_API_KEY`) из окружения. После правки конфига —
одна строка:

```bash
bash tools/bot-service.sh restart
```

Выключить модель (только правила): `"llm": {"enabled": false}` в конфиге или
`LIFEOS_LLM_ENABLED=0` в окружении. Без ключа поведение прежнее — правила,
`engine="rules"`, ни одного сетевого вызова.

## Настройки «сколько думать»

| Ключ конфига | Env | По умолчанию | Зачем |
|---|---|---|---|
| `llm.reasoning_effort` | `LIFEOS_LLM_REASONING_EFFORT` | `xhigh` | общий уровень, если отдельные не заданы |
| `llm.parse_effort` | `LIFEOS_LLM_PARSE_EFFORT` | `medium` | разбор фразы: извлечь поля, а не рассуждать |
| `llm.answer_effort` | `LIFEOS_LLM_ANSWER_EFFORT` | `xhigh` | ответ по готовым числам: аккуратная формулировка |
| `llm.parse_timeout` | `LIFEOS_LLM_PARSE_TIMEOUT` | `8` с | потолок ожидания разбора |
| `llm.answer_timeout` | `LIFEOS_LLM_ANSWER_TIMEOUT` | `25` с | потолок ожидания ответа |

Пустая строка в effort — не отправлять подсказку вовсе (провайдер без
поддержки). Неизвестное значение — `ConfigError`, а не тихое «как-нибудь».

## Что происходит с сообщением

1. **Правила первыми.** Еда с граммами, сумма, вода, сон, привычка, дело с
   явной датой/временем — разбираются без сети (`engine="rules"`), модель не
   вызывается.
2. **Модель — вторым слоем.** Если правила уверены меньше чем на 0.7
   (свободная мысль, «я сегодня как выжатый лимон», дело без глагола/даты,
   «мысль: …» без книги), фраза уходит модели. В подсказке перечислены **все**
   действия: дела, расход/доход, еда с граммами, вода/сон/вес/тренировка
   (legacy), привычка, книга/цитата/выжимка/прогресс, мысль, чек-ин энергии,
   практика, вопрос о данных. Модель возвращает `{intent, поля, confidence,
   ask?}`; исходный текст человека сохраняется в записи.
3. **Низкая уверенность — вопрос, не Инбокс.** `confidence < 0.55` или
   `intent=inbox/clarify`: бот задаёт один вопрос и даёт 2–4 кнопки с
   вариантами; выбранный вариант применяется по клику. Если модель не дала
   пригодного разбора, а правила сомневаются сильнее 0.45 — тоже вопрос
   («Не уверен, что это. Как сохранить?»), а не запись наугад.
4. **Вопросы о данных.** Код всегда считает агрегаты по БД (`store_v4.
   answer_question`). Модель может только переписать готовые числа
   человеческим языком; каждое число ответа проверяется на вхождение в
   переданные агрегаты. Придумала число — ответ отбрасывается, остаётся
   ответ кода. Модель зовётся только если разбор фразы был на правилах:
   один вызов модели на сообщение (парс ИЛИ ответ, не оба).
5. **Надёжность.** Таймауты 8 с/25 с, любой сбой/невалидный JSON — откат на
   правила без технотекста в ответе. Одинаковые фразы кэшируются на 10 минут
   (сбой модели не кэшируется — следующая попытка снова спросит).
   `usage_events.meta_json`: `engine="llm"|"rules"`, `latency_ms`, у ответа
   ещё `stage="answer"`.
6. **Ключ.** `repr(settings)` и `repr(gateway)` без ключа; в логах ключа нет
   (проверяется тестом).

## Проверка на настоящем api.samp.team

Модель `deepseek-v4.1-flash-1017`, ключ из `config/config.json`.

```
reasoning: {"effort": "xhigh"} → HTTP 200, 4.9 c, ответ {"ok": true, "echo": "pong"}
провайдер не ругается 400; на 400 предусмотрен один повтор без поля + warning
```

### Пять фраз владельца — дословные ответы бота (живой прогон, временная БД)

| Фраза | Ответ бота | Кто разобрал | Время |
|---|---|---|---|
| поздно не сплю | «Как записать «поздно не сплю»?» (кнопки: «Мысль в дневник», «Привычка «Не спать поздно»», «Отметка состояния») | LLM · clarify | 5.3 с |
| дела life off | «Записал в журнал: «дела life off» (+1 очко)» | правила · journal (модель не успела за 8 с) | 8.3 с |
| я сегодня как выжатый лимон после планёрки | «Не уверен, что это. Как сохранить?» (кнопки: «Это мысль», «В инбокс») | правила · clarify (таймаут модели) | 8.3 с |
| на такси ушло четыреста | «Записал расход: 400 ₽ — Транспорт, Карта» | правила · expense | 0.0 с |
| купил кроссовки за 8 900 | «Записал расход: 8 900 ₽ — Одежда, Карта» | правила · expense | 0.0 с |

Провайдер в этот момент отвечал неравномерно: два вызова не уложились в 8 с и
тихо ушли на правила — это и есть заявленный откат (вместо выдуманного дела
бот задал вопрос). В других прогонах модель успевала: «Это запись привычки
«не спать поздно» или заметка в дневник?» с кнопками «Мысль в дневник» /
«Привычка «не ложиться поздно»»; «Не понял фразу — показать дела или записать
новое?»; для «лимон» — `journal` с темами «работа» и настроением «усталость»
(4.9 с, engine=llm).

### Что модель говорит про фразы, которые правила уже понимают
(прямой вызов, effort `medium`, как доказательство «свободы»)

| Фраза | Разбор модели |
|---|---|
| на такси ушло четыреста | expense, 400 ₽, Транспорт, confidence 0.93 |
| купил кроссовки за 8 900 | expense, 8900 ₽, Обувь, confidence 0.95 |
| поздно не сплю | clarify 0.3 + 3 варианта (дневник / привычка / отметка состояния) |
| дела life off | clarify 0.25 + 3 варианта (дела на сегодня / мысль / топ задач) |
| я сегодня как выжатый лимон | journal, темы работа, настроение усталость, confidence 0.62 |

Вывод: «на такси» и «кроссовки» правила понимают верно, модель им не нужна;
три свободные фразы модель понимает по-разному, но осмысленно, и при низкой
уверенности честно спрашивает.

## Что изменено

- `app/server/settings.py` — `llm_reasoning_effort`, `llm_parse_effort`,
  `llm_answer_effort`, `llm_parse_timeout`, `llm_answer_timeout`; env
  `LIFEOS_LLM_*`; уровни в `safe_dict`; ключ остаётся `repr=False`.
- `app/bot/intent.py` — `OpenAICompatibleGateway`: стандартное поле
  `reasoning: {effort}`, повтор без него на HTTP 400 (один раз, с warning),
  таймаут на вызов, ключ не логируется; оценка КБЖУ по-прежнему `xhigh`.
- `app/bot/intent_v4.py` — правила первыми (`rules_confidence`), модель
  вторым слоем, кэш 10 минут, `clarify` с вариантами и кнопками, поддержка
  `action`, `confidence`, `ask`; `legacy`-действия (вода/сон/вес/тренировка)
  через общий валидатор; `AnswerWriter` (пересказ агрегатов, проверка чисел,
  усилие `xhigh`, таймаут 25 с); `build_router` берёт усилия и таймауты из
  настроек.
- `app/bot/handlers.py` — `latency_ms` и `engine` в `usage_events`; ответ
  моделью только для вопросов, разобранных правилами; вопрос с кнопками
  сохраняется в `settings_kv` и применяется по callback `v4:pick:<i>`.
- `config/config.example.json`, `config/README.md` — новые ключи и как включить.
- `app/tests/test_bot_llm.py` — 31 новый тест (mock-гейтвей, 20 свободных фраз,
  низкая уверенность/кнопки, ошибки/таймауты, кэш, `reasoning`/400, числа
  ответа, usage, настройки).

## Ограничения и риски

- На медленной сети (VPN) разбор иногда не укладывается в 8 с и тихо падает
  на правила — так и задумано; если хочется больше модельных ответов, увеличь
  `llm.parse_timeout` (например, 12–15) или поставь `parse_effort: "low"`.
  В живых прогонах типичный ответ модели 2–6 с, но бывают выбросы 8–10 с,
  а xhigh-ответ один раз занял 27.7 с (у ответа таймаут 25 с — тоже откат).
- Модель может ошибиться в классификации свободной фразы; поэтому
  низкая уверенность → вопрос, а не запись, а исходный текст всегда
  сохраняется в записи.
- Ответы о данных модель только пересказывает; числа сверяются с агрегатами,
  но стиль формулировки — на её совести (не придумывает числа).
- Ключ не проверялся на утечку в реальные логи сервиса: тест проверяет
  отсутствие ключа в `repr` и в перехваченном логе. В `config/config.json`
  ключ уже стоит — не коммитить.
