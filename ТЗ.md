# ТЗ: Life OS — персональный Telegram-агент + Obsidian + дашборд

**Версия:** 1.0 · **Дата:** 2026-11-16 · **Статус:** к разработке
**Владелец:** пользователь (не программист) · **Исполнитель:** команда субагентов DSH

---

## 1. Продукт и цель

Персональный AI-ассистент в Telegram, который сам пишет пользователю несколько раз в день,
подробно расспрашивает про жизнь (задачи, еда, тренировки, цели, состояние, мысли),
складывает всё в Obsidian-базу пользователя структурно и по-человечески,
и показывает аналитику на локальном дашборде, который открывается с Mac в браузере.

Ключевой принцип: **бот — не просто опросник, а внимательный собеседник**, который
задаёт уточняющие вопросы («очень очень подробно»), но не перегружает и не спамит.

## 2. Пользователь и ежедневный сценарий

- Один пользователь, ТЗ Europe/Moscow, macOS 27, база Obsidian:
  `/Users/user/Documents/чисто лайфик обсидиан/чисто лайфик`
- Утро (08:30): «привет, какой план на день?» → 3 главные задачи, время, проверка целей.
- День (14:00): «что ел? вода? как энергия?» → приёмы пищи, вода, состояние.
- Вечер (21:30): «как тренировка? что по задачам? итог дня, что тревожит?» →
  тренировка (тип/время/нагрузка/самочувствие), задачи (сделано/перенесено),
  питание за день, настроение/энергия/фокус, мысли и рефлексия.
- Воскресенье 21:00: недельный дайджест + вопросы на неделю вперёд (nice-to-have, фаза 2).
- В любой момент пользователь может написать боту свободным текстом — бот ответит
  по-человечески, извлечёт данные, сохранит.

## 3. Функциональные требования

### 3.1 Telegram-бот
- Работает как Telegram Bot (Bot API, long polling), один разрешённый chat_id.
- Токен и chat_id — из конфига. Чужие пользователи игнорируются.
- Отправка: текст (до 4000 символов, при превышении режется на части).
- Приём: текст и команды; неизвестное — вежливо направляется к смыслу бота.
- Устойчивость: таймауты, 429 с retry_after, 409 conflict (два процесса) — backoff.
- Dry-run режим: без реального Telegram, пишет в лог.

### 3.2 Диалоговый движок (опросник)
- Слоты: morning / midday / evening (+ weekly факультативно).
- На старте слота: приветствие + вопрос №1; далее по одному вопросу за сообщение.
- Ответ короткий (<30 символов) и вопрос требует деталей → до `max_followups`
  (по умолчанию 2) уточняющих вопросов через LLM; дальше идём к следующему вопросу.
- Пользователь может: ответить на несколько пунктов сразу, написать «-»/«пропусти»
  (пропуск), «стоп» (прервать сессию), «/статус».
- Все ответы сохраняются в БД немедленно + структурированные записи (entry).
- Пропущенный слот не догоняется насильно: в конце дня один мягкий пинг, если
  вечерний слот пропущен (опционально, конфигурируемо).

### 3.3 Команды
`/start`, `/pause`, `/resume`, `/status`, `/today`, `/report`, `/goals`, `/add_goal`,
`/skip`, `/help`, `/дизайн` (перегенерировать дашборд). Русские алиасы: старт, пауза,
продолжить, статус, сегодня, отчёт, цели, помощь, пропустить.

### 3.4 Извлечение данных
Из свободного ответа LLM извлекает: категорию (tasks/food/training/goals/mood/journal/
sleep/water/other), человекочитаемый текст записи и metrics (JSON, только то, что явно
следует из ответа; ничего не додумывать). При недоступности LLM — эвристика по слотам,
запись сохраняется как есть, а числа с единицами (мл, ккал, ч, мин, км, кг, г белка)
вытаскивает regex-эвристика; категория уточняется по тексту вопроса
(ответ на «что ел» — food, даже если в ответе мало ключевых слов).
Нормализуются разделители тысяч: «2 000 мл» → 2000. «Встреча 30 минут» не считается
тренировкой; «час за компом» не считается сном.

### 3.5 Obsidian
- Ежедневная заметка `01 Daily/YYYY-MM-DD.md`: создаётся из
  `Шаблоны/Шаблон - День.md` (подстановка даты), затем в конец добавляются блоки
  `## Еда (агент)`, `## Тренировка (агент)`, `## Задачи (агент)`, `## Цели (агент)`,
  `## Мысли (агент)` с пунктами и временем.
- Идемпотентность: каждая запись один раз, маркер `<!-- lifeos:entry:ID -->`.
  Существующее содержимое пользователя НЕ трогаем, только дописываем в конец.
- `Проекты/Life OS/Цели.md` — таблица целей с прогрессом (перегенерируется целиком
  между маркерами `<!-- lifeos:goals:start -->` … `end`), ссылки `[[Цель ...]]`.
- Зеркало данных: `Life OS/data/entries.jsonl`, `goals.json` (machine-readable,
  для Dataview/скриптов). Включается конфигом.
- Ошибки записи (нет папки, запрет) логируются, бот продолжает работать, данные
  остаются в БД и допишутся при следующем запуске (флаг written).

### 3.6 Дашборд
- Самостоятельная HTML-страница `dashboard/index.html` (без интернета, без CDN),
  открывается двойным кликом в браузере Mac. Данные встроены в страницу.
- Дизайн — по референсам пользователя (см. `PROJECT_CONTEXT.md` §4): светлый,
  воздушный, крупные скруглённые карточки, мягкие тени, пастельные акценты.
- Карточки: Сегодня (чек-ины слотов), Цели (прогресс-бары), Сон (линия 14 дней),
  Тренировки (бары по неделе + стрик), Питание/вода, Настроение/энергия (линия),
  Привычки (список), Журнал (5 последних записей), Хитмап чек-инов 8 недель.
- Автоперегенерация при каждой новой записи; кнопка «Обновить» и обновление страницы.
- Пустые данные: аккуратные заглушки, без «NaN».

### 3.7 Установка и эксплуатация
- `install.sh`: копирует проект в `~/Library/Application Support/LifeOS`, создаёт
  конфиг (chmod 600), подхватывает LLM-ключ из `~/.dsh/.credentials.yaml` если есть,
  ставит LaunchAgent `com.lifeos.agent` (KeepAlive, RunAtLoad), запускает, печатает статус.
- `uninstall.sh`: выгружает агент, оставляет данные (или `--purge`).
- Логи: `~/Library/Logs/LifeOS/agent.log` (ротация >5 МБ), ошибки — тоже туда.
- `dsh`-сессии в фоне не живут — фоновость обеспечивает launchd + python3 (stdlib).

## 4. Архитектура

```
launchd (com.lifeos.agent)
   └─ python3 src/main.py  (cwd = install dir)
        ├─ telegram.py   ← Bot API (urllib, stdlib)
        ├─ scheduler.py  → слоты по Europe/Moscow, сессии опроса
        ├─ storage.py    → SQLite (data/lifeos.db)
        ├─ llm.py        → SAMP gateway /v1/chat/completions (deepseek-v4.1-flash-1017),
        │                  fallback: скриптованные вопросы без LLM
        ├─ prompts.py    → тексты вопросов, системный промпт, follow-up
        ├─ parsing.py    → ответ → entry {category, text, metrics}
        ├─ obsidian.py   → дневник, цели, зеркало JSONL
        └─ dashboard_data.py → dashboard/index.html + data.json
```

Один процесс, один поток, один цикл: long-poll getUpdates (timeout 20 c) +
`tick()` планировщика каждые ~15 c. Без внешних Python-пакетов (только stdlib).

## 5. Данные (SQLite)

```sql
messages(id INTEGER PK, chat_id INTEGER, direction TEXT, text TEXT, ts TEXT, slot TEXT);
entries(id INTEGER PK, date TEXT, ts TEXT, slot TEXT, category TEXT, title TEXT,
        text TEXT, raw TEXT, metrics TEXT, written INTEGER DEFAULT 0);
goals(id INTEGER PK, title TEXT, target TEXT, current TEXT, deadline TEXT,
      status TEXT DEFAULT 'active', note TEXT, created TEXT, updated TEXT);
habits(id INTEGER PK, name TEXT UNIQUE, streak INTEGER DEFAULT 0,
       last_done TEXT, total INTEGER DEFAULT 0);
kv(key TEXT PK, value TEXT);
```

`entries.metrics` — JSON: `sleep_h, water_ml, calories, protein_g, weight_kg,
training_type, duration_min, mood(1-5), energy(1-5), focus(1-5), tasks_done[],
tasks_planned[]` — поле подставляется только если явно сказано.

## 6. Конфиг (config/config.json, пример — config.example.json)

```json
{
  "telegram": {"token": "", "allowed_chat_id": 0,
                "api_base": "https://api.telegram.org"},
  "obsidian": {"enabled": true,
    "vault_path": "/Users/user/Documents/чисто лайфик обсидиан/чисто лайфик",
    "daily_folder": "01 Daily", "template_path": "Шаблоны/Шаблон - День.md",
    "goals_path": "Проекты/Life OS/Цели.md", "data_folder": "Life OS/data",
    "write_mirror": true},
  "llm": {"enabled": true, "base_url": "https://api.samp.team/v1",
          "model": "deepseek-v4.1-flash-1017", "api_key": "",
          "timeout": 60, "max_followups": 2},
  "schedule": {
    "morning": {"time": "08:30", "enabled": true},
    "midday":  {"time": "14:00", "enabled": true},
    "evening": {"time": "21:30", "enabled": true},
    "weekly":  {"time": "21:00", "weekday": 6, "enabled": false}
  },
  "paths": {"db": "data/lifeos.db", "logs": "data/logs",
            "dashboard_out": "dashboard/index.html"},
  "app": {"name": "Life OS", "timezone": "Europe/Moscow", "lang": "ru",
          "onboarding": true, "quiet_hours": ["23:00", "08:00"]}
}
```

Ключи `app.onboarding` (знакомство по /start до первого опроса) и
`app.quiet_hours` (тихие часы: плановые сессии не стартуют) — в config.example.json
включены; в DEFAULTS выключены, чтобы не мешать тестам и dev-запускам.

## 7. Нефункциональные требования

- Python 3.9+ (`/usr/bin/python3` = 3.9.6 на этой машине, `python3` из PATH = 3.13),
  только stdlib.
- Время: `zoneinfo.ZoneInfo("Europe/Moscow")`; сравнение дат по локальной дате.
- Offline-first: интернет нужен только Telegram и (опционально) LLM.
- Приватность: данные только локально (SQLite + Obsidian), токен/ключ в файлах 600.
- Стабильность: любое исключение в цикле ловится, логируется, процесс живёт.
- Читаемость кода: русские комментарии в ключевых местах, docstring модуля.
- Тесты: `python3 -m unittest discover tests`, e2e на мок-сервере Telegram.

## 8. Приёмочные критерии (Definition of Done)

1. `python3 -m unittest discover tests -v` — зелёный.
2. E2E (мок API): инициируется утренний слот → бот задаёт вопросы → пользователь
   отвечает → записи появляются в тестовой обсидиан-``vault`` (daily note + targets),
   `entries.written=1`, дашборд перегенерирован и содержит данные; повторный прогон
   не дублирует записи.
3. `/status`, `/today`, `/help` работают; неверные команды не ломают цикл.
4. LLM выключен / недоступен → опрос работает в скриптованном режиме, данные пишутся.
5. Свежий конфиг с реальным токеном и chat_id → `install.sh` ставит агент, через
   минуту в Telegram приходит сообщение по расписанию; `launchctl list | grep lifeos`
   показывает запущенный процесс.
6. Дашборд открывается в браузере, выглядит как референс, данные видны, пустые
   состояния аккуратны, консольных ошибок нет.
7. README (по-русски) позволяет пользователю самому: создать бота, вставить токен,
   поставить/снять с автозапуска, увидеть дашборд.

## 9. Ограничения и риски

- Токен бота создаёт пользователь через @BotFather — до этого реальный запуск невозможен,
  всё остальное тестируется на моке.
- SAMP-гейтвей (LLM) нестабилен: glm-5.3-prime ранее отдавал tools_unsupported;
  агент не должен от него зависеть — LLM опционален, есть fallback.
- Запись в Obсидиан из песочницы DSH может быть запрещена: тесты пишут в temp-vault,
  боевая запись идёт из launchd (вне песочницы DSH).
- Obsidian может быть открыт — дописывание в конец файла безопасно (без перезаписи).
- Двойной запуск (вручную + launchd) — защита pid-локом.
